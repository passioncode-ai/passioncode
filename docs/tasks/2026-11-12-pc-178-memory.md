# PC-178: `setup` installs the agents' wiki memory (obsidian-wiki and Obsidian)

Status: specification and build, 2026-11-12; row PC-178 in [the backlog](../backlog.md); decision
[ADR-0006](../adr/0006-setup-installs-the-agents-wiki-memory.md). Read at launcher `a4e9bfb` (origin/main).

## Why

The operator, 2026-11-12, verbatim: «давай передадим в анбординг скрипт passioncode организации установку сразу туда
вместе с софтом и обсидиан мемори вот эту чтобы она там работала и обсидиан вместе с ней конечно же». The organization's
onboarding command, `npx @passioncode-ai/passioncode@latest setup`, installs the agents' wiki memory with the apps: the
open-source `obsidian-wiki` package (github.com/Ar9av/obsidian-wiki, MIT, PyPI `obsidian-wiki`) with a vault of its own,
and Obsidian, so the memory works right after setup on every machine and for every macOS user (Studio spaces included).
Only the mechanics travel: never any vault content.

## Decided here, where the decisions above were silent

- **Ids.** `--with` and `--without` take `obsidian`, `wiki` and `memory` (both). `--with fabric` alone leaves the memory
  out, as it leaves the other apps out.
- **Trains.** A release train pins PassionCode.ai apps only (`trains.load` still checks `catalog.byId`); obsidian-wiki is
  pinned by the launcher release, as the skills are; Obsidian follows its latest release and updates itself in the app.
- **`--no-apps`** leaves the memory out too (it is the recovery command's flag, `setup --yes --no-apps --train none`,
  which must install nothing new); so does a saved train this launcher cannot use, and `doctor` then names "first make
  the release train usable" before `setup --with wiki`.
- **A vault folder that holds files** (`~/.wiki` the person already uses) is never made a vault: the memory
  offer is `unavailable`, never asked, and its note names `--wiki-vault`. The same for a missing uv.
- **Upgrade only what uv installed.** The `tool` repair runs only when `uv tool list` names obsidian-wiki; a copy pipx or
  pip installed is named with the step, never replaced under it.
- **Not on PATH.** uv puts the command in `~/.local/bin`, which a new Mac's shell may not search: `memory.wiki.path` is a
  warning whose fix is `uv tool update-shell` (an agent can run it; setup does not edit shell files on its own).
- **Agent folders.** obsidian-wiki's setup makes `~/.codex/skills`, `~/.gemini/skills` and more for agents that may not
  be installed (observed in a throwaway home, 2026-11-12). The launcher counted any such folder as the agent and would
  have registered MCP servers there, so a folder that holds only skill folders no longer counts
  (`lib/launcher.js` `agentFolder`; an empty folder still does).
- **Hooks only for a set-up wiki.** The `memory.hooks` rows appear only where Claude Code's CLI answers and an
  obsidian-wiki config exists (superseded in the fix round: no longer by `~/.claude` existing). `obsidian-wiki doctor`'s
  hints are no longer relayed at all (superseded in round 4: a fix names only commands on the allowlist, or a fixed text;
  see "Round 4").
- **Opening.** Obsidian is opened once after it is installed, like every app. When setup made a vault, its step names
  that vault to open in Obsidian, or Obsidian's download page where Obsidian is not installed (superseded: the general
  guide gives way to it). The agents write the vault without the app.

## Open

- `obsidian-wiki setup` rewrites the config (in 2026.8 it dropped a person's other keys; 2026.11.4's `write_config`
  keeps them). The rule stands: the launcher never runs setup over a config and never hands it out as a fix.
- Windows: obsidian-wiki installs through uv as on macOS; Obsidian's Windows installer is not run (its page is named).
  The `PC-178` tests simulate macOS and Linux with shell-script stand-ins, so they skip on Windows like the other
  `MAC_SIM` cases.
- A machine where obsidian-wiki is not on PATH gets the warning, not a change: whether setup should run
  `uv tool update-shell` itself is the operator's call.
