# PC-123: anonymous usage and error counts, on by default

Status: plan, 2026-11-04; what shipped is [the event catalogue](../analytics-events.md), which supersedes the tables below (`iid` is the installation id and `install_id` its copy for the family's joins, `surface` and `existing` were added, and the shared `analytics: false` is read once to keep a "no" already given). Row PC-123 in [the backlog](../backlog.md); target 0.2.76 by 2026-11-07.

## What the operator decided

Item D of the organization's plan for sessions on demand (decided 2026-11-04): anonymous usage and error analytics on
by default for new and existing installations, a notice at first start (not a question), a switch per product (one
product's switch never turns another off). The launcher follows the convention the other products already ship
(Fabric Dashboards FD-136, Fabric Switchboard SB-246), adapted to a command-line program run through `npx`.

## What is sent

To the organization's Aptabase host, `https://analytics.passioncode.ai`, app "PassionCode" (platform row PLAT-132),
`POST /api/v0/events`, in one batch at the end of a command, at most 25 events, with a 2-second ceiling so a command
never waits on the network. A failed send is dropped, never retried in a later run and never written to disk.

| Event | When | Properties |
| --- | --- | --- |
| `app_installed` | the first command on this machine that sends anything | none |
| `app_updated` | the first command after the launcher's version changed | `from` (the previous version) |
| `app_active` | once per UTC day, with the first command of the day | none |
| `command_run` | every command, when it ends | `command` (setup, doctor, update, status, restore, config, uninstall, permissions, analytics, help), `outcome` (ok, failed, usage), `duration` (a bucket: under-1s, 1-10s, 10-60s, over-60s), `json` (true or false) |
| `app_error` | a command ends with exit 1 | `where` (the command), `code` (`other` for now; fixed codes per failure are added to the catalogue first) |

Every event carries what the Aptabase SDKs carry (the launcher version, the OS name and version, the locale) plus
`install_id` (the shared `PassionCode/installation.json` id, created once if absent, the same file the apps use) and
`environment` (`production`, or `sandbox` for a development checkout).

Never sent: a path, a file name, a user or folder name, a rule, an argument, an app id the person typed, a token, an
error message, the content of any file. Properties are fixed words and counts only.

## The notice

The first command that would send something prints one line on stderr, once per machine, before it sends:

> The PassionCode launcher sends anonymous usage and error counts to improve it. Turn them off for the launcher: npx @passioncode-ai/passioncode@latest analytics off (each PassionCode app has its own switch).

A `--json` run and the SessionStart self-update never print it; they send nothing until a run that is neither has
printed it. "Shown" is stored in the launcher's own state.

## The switch

`passioncode analytics off`, `on` and `status` (`--json`), saved in the launcher's own state (absent means on).
`PASSIONCODE_ANALYTICS=off` or `DO_NOT_TRACK=1` turns it off for one process. Off sends nothing and stores nothing new.
The shared file's `analytics` field is read once, at the first counting run, to keep a "no" already given (superseded: see the catalogue); after that one product's switch never turns another off.

## The key

Only a release build carries the App Key: the publish job writes it into the packed package from the repository secret
filled from the organization's vault. A checkout or a build without it sends nothing
and `analytics status` says so.
