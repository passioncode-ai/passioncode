# Handoff: launcher 0.1.5 — the working rules as a skill, an honest status, no machine paths (2026-09-29)

## Objective

Make the organisation's working rules reach every contributor's agent (they lived only in
org-index `RULES.md` and one person's private agent instructions), fix `passioncode
status`, take the machine paths out of `family.json`, relicense the launcher like the
public tools, and ship Fabric Agent Adapter 0.4.3 in the set. No npm publish, and no
`passioncode update` on any machine: both are the integrator's.

## Done

- **`working-in-passioncode`** in the self plugin
  (`plugin/passioncode/skills/working-in-passioncode/`): the org map, landing, CI, handoffs,
  decisions/ids/leases, secrets, licensing, the privacy gate, releases and pins, pointing to
  org-index for each; detail in `references/releasing.md` and `references/publishing.md`.
  Description 944 characters (5% headroom under 1024), body 200 lines. Evals:
  `test/evals/working-in-passioncode/triggers.json` (12 positive, 12 near-miss negative,
  both languages) and `scenarios.json` (6 scenarios, each naming its trap and at least three observables).
  `test/skill.test.js` holds every self-plugin skill to the standard.
- **Hub linking.** Nothing was missing in the launcher: the hub links every member's
  skills, the self plugin's included; `passioncode hub: 0/0` meant the self plugin had no
  skill. A smoke install of the vendored payload into an empty `HOME` now reports
  `passioncode 0.1.5 … hub: 1/1` and links `~/.cursor/skills/working-in-passioncode`
  through the hub.
- **`status`** reads `~/.passioncode/current/manifest.json` (the installed release), not the
  payload beside the CLI; `package` still reports the payload's version and `source` says
  which one was described. Tests: `status reads the installed release, not the package
  payload it is run from`, `status before any install describes the package payload`
  (both failed before the fix).
- **`family.json`** carries no `checkout` paths (RULES §7). Local clones are
  `PASSIONCODE_CHECKOUT_ROOT=<dir>` (reads `<dir>/<repository name>`) or
  `PASSIONCODE_CHECKOUT_<MEMBER>=<path>`; a `checkout` key is refused. The operator's fast
  path: `PASSIONCODE_CHECKOUT_ROOT=<projects dir>` plus
  `PASSIONCODE_CHECKOUT_OBSERVATORY_LOG=<the engine clone>`, whose directory name differs
  from its repository's.
- **License.** Source-available (`PolyForm-Noncommercial-1.0.0 OR
  LicenseRef-PolyForm-Internal-Use-1.0.0`) in `LICENSE`, `package.json`, the self plugin and
  the skill; v0.1.4 and earlier stay MIT. `AGENTS.md` no longer claims there is no hosted CI. `CLA.md`, `CONTRIBUTING.md`, PR template. The
  payload lists each member under its own manifest's license (observatory-log v0.8.1 is
  still MIT; the adapter 0.4.3 is source-available).
- **Version.** 0.1.5, not 0.1.4: `v0.1.4` was already tagged (and published to npm) by
  another session, and tags never move. `family.json`: adapter `v0.4.3`; observatory-log
  stays `v0.8.1` for the integrator to bump after the engine's next release.
